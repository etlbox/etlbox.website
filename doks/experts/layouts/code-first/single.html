Why testable ETL is a better result

If the flow is code, it can have tests. We do not wait for a nightly run to learn that a null in column 14 broke the load. We use TDD: write the test for the rule, watch it fail, then write the transform.

Catch it in CI

A renamed API field, a late invoice, a currency rule — they show up as a red test before they show up in finance. Production should not be the first place the rule runs.

Change without a war room

That is how we keep incremental loads idempotent and prove a merge does not double-count. Your team can open the repo in six months and change the flow without a war room.

A typical example: “net amount is gross minus discount, unless the currency is not EUR, in which case convert first.” That is a unit test, not a workshop. The destination table is an integration test.

Why AI likes code-first

A canvas is a picture. Code is text an AI can read, write, and we can still test. That is why we work unusually fast — and why we are good at pipelines that need AI, not just pipelines built with it.

We ship faster

We use AI ourselves on the repo: drafts, reviews, the boring glue. It only works because the toolbox is code — ETLBox, C#, tests. A drag-and-drop job gives AI nothing to hold on to.

AI in your flow

ETLBox has AI support. We put it in the pipeline where a mapping table runs out — extract, classify, decide — and keep the rest as tests you can run in CI. Next level, not a science project.

We built the tools we use

ETLBox exists because we needed a .NET library that could pull from databases and APIs, transform in memory, and load hard — without becoming a product you have to rent. It now has AI support. Customer projects are where the library stays honest. When we take a job, we bring the connectors — and the AI — not a certification slide.

What “good” looks like

A pipeline nobody has to babysit. Four checks we use on every project — not a methodology, just what we refuse to skip.

Incremental

Load what changed. A full reload is a last resort — when the source is tiny and the night is long.

Idempotent

Run the job twice. The table does not grow. Yesterday’s load and today’s load agree.

Observable

You can see what ran, what failed, and which row caused it — without opening a debugger on the server.

Yours

The repo is yours when we leave. We are not a runtime you cannot walk away from.
